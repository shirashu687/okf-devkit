# 0003. 外部コードソースを名前で参照する

- 決定日 2026-11-28
- 状態は設計方針として採用。初回提供の起点は [Issue #61](https://github.com/shirashu687/okf-devkit/issues/61)。

## 背景

コードと文書を別々に管理する構成では、文書側の `code_globs` に相対パスやジャンクションを使うと実ファイルに届く場合がある。変更の逆引きには、ファイルの場所に加えてどの Git の履歴を読むかも必要になる。開発者と CI でチェックアウトの配置が異なり、文書だけを置く環境もある。

## 選択肢

| 案 | 利点 | 負担 |
| --- | --- | --- |
| 文書に外部ファイルの相対パスを書く | 既存の `code_globs` の形式で書ける | 文書が配置順に依存し、変更を調べる Git の指定が別途必要 |
| 共有するソース名と配置先を登録する | 文書の参照と Git 履歴の指定に同じ名前を使える | ソースの登録が必要 |
| 共有するソース名を使い、環境ごとに設定ファイルを用意する | 構成全体を環境ごとに調整できる | 配置先だけを変える場合も設定全体を管理する必要がある |

## 決定

`okf.yml` の `code_sources` にソース名と標準の配置先 `path` を宣言する。配置先を変える環境は、宣言した `path_env` の環境変数でそのソースの `path` を上書きできる。相対パスの起点は文書プロジェクトルートとする。

```yaml
code_sources:
  - name: app
    path: ../app-repo
    path_env: APP_REPO_DIR
```

文書は `code_globs` で `app:src/**` のように、ソース名とそのリポジトリからの相対パターンを指定する。接頭辞のないパターンは文書プロジェクト側で従来どおり解決する。OKF 文書の `sources` は出典の記述に使う。

## 理由

- ソース名を共有すると、同じ `src/login.ts` が複数リポジトリにあっても、文書がどちらを根拠にしたか分かる。
- 環境変数で配置先だけを上書きすると、文書の参照や設定の残りを各環境で共有できる。
- 文書だけの環境でも他の項目を検査できるよう、外部ソースの未配置や未解決の参照を警告で示す。

## 影響

- 初回は `lint` による外部コードの照合と、`affected --source <name> --base <ref>` による逆引きを提供する。外部ソースの変更入力は `--base` に絞る。指定ソースの変更パスはそのソースの `code_globs` と照合し、文書側の `layer_map` は従来のローカル変更の調査に使う。
- 外部ソースの `affected` は、指定した比較対象と現在の HEAD の共通祖先から HEAD までの変更と、作業ツリーの未コミット変更を対象にする。指定した比較対象や共通祖先を特定できない場合は差分未確認とする。
- 外部ソースの照合ができない場合は警告で示し、通常の `lint` は他の検査を続け、`affected` は差分が未確認であることを表示して終了コード `0` を返す。`lint --strict` では既存どおり警告が終了コード `1` の対象になる。
- 初回の `stale` は外部コードの更新時刻を未検証と表示する。外部履歴による鮮度判定と `log` は後続で扱う。反映済み SHA の管理は [Issue #62](https://github.com/shirashu687/okf-devkit/issues/62) で扱う。
- Python と Node.js に同じ仕様を適用する。 [Decision Record 0001](/project/decisions/0001-node-runtime.md)
