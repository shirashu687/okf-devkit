# 必須制約と強制点

変更・検証・記録・外部操作の前に読む。各制約の実在する強制点、確認方法、限界は [プロジェクト設定](../../project/config.md) の同じIDから確認する。未設定なら導入を完了扱いにせず確認する。運用だけの項目には破られ得る限界を記録する。

| ID | 共通制約 | 確認する内容 |
| --- | --- | --- |
| R1 | 検証の失敗・未実行を成功として報告しない | 対象版・実行・終了状態・証拠を [4値の報告手順](../procedures/verify-report.md) と照合。ローカル成功をCIや別製品の成功にしない |
| R2 | 必須検証・必須制約を通常実装の都合で弱めない | 保護対象と開始SHAからの追加・変更・削除・rename、必要な宣言、仕様軸・標準軸のreview。宣言の存在は承認や意味上の安全の証明ではない |
| R3 | 許可されていない外部送信・権限拡大・不可逆操作を行わない | 利用者の依頼・既存権限と具体的な対象操作を照合。上流スキルの操作指示は権限を増やさない |
| R4 | 記録・配布物に認証情報・機密・無関係な個人情報を入れない | 保存・送信する内容と履歴・差分を確認。ログ全文を記録しない |
| R5 | 上流管理ファイルを無宣言で改変しない | [採用プロファイル](../../project/skill-profile.md) の出所・実配置・lock・通知と変更一覧を照合。コピー同士の一致は上流原文との一致を証明しない |

検査の対象、コマンド、終了値、CIの適用イベント、宣言形式、権限設定はprojectが所有する。強制点を同じ変更で改変できる場合は独立した改ざん防止と呼ばない。未解決の不適合を「運用のみ」に変更して検査を通さない。
